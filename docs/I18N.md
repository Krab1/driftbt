# Translations

Drift translates its own interface with a small layer of its own (`src/lib/i18n.svelte.ts`); there is no library. See D-76.

## How it works
- The **English text is the key**: `t("Add torrent")`, `t("{n} active", { n })`, and for numbers `tn("{n} torrent", "{n} torrents", count)`.
- A language is one file, `src/locales/<code>.json`, mapping the English text to its translation. For `tn` the key is the second (plural) English text and the value is an object with one string per plural form of that language (`one`, `few`, `many`, `other`).
- Text with no entry shows in English, so a language can be finished one screen at a time.
- Settings → General → Language chooses `system` (follow the computer) or a code. The choice is saved in settings and remembered in the browser storage so the window opens in it. A region falls back to its language (`pt-BR` to `pt`), then English.
- Dates and numbers use the chosen language (`locale()`).
- A development build also offers "Pseudo" (code `xx`): every text is stretched and accented so clipped layouts show up.

## Rules for code
- The first argument of `t` / `tn` must be a **plain quoted string** (no template string, no variable): the script finds texts by reading the source. Put changing parts in `{placeholders}` and pass them as the second argument.
- Do not build sentences from pieces (`t("You have") + n + t("files")`): translators need the whole sentence.
- In a component where `t` is already a variable (a torrent, say), import it as `import { t as tr }`; the script knows `tr`.

## Adding or updating a language
1. Add `{ code, name }` (the language's own name) to `LANGUAGES` in `src/lib/i18n.svelte.ts`.
2. `node scripts/i18n.mjs --todo <code>` prints the texts still missing as JSON; translate the values into `src/locales/<code>.json`.
3. `npm run check` runs `node scripts/i18n.mjs`: it fails on texts no longer used, `{placeholders}` that differ from English, and plural forms the language does not use. `--strict` also fails on missing texts.
